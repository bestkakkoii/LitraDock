# ADR-0010: Explicit permitted repository snapshots

2026-09-12. Implemented candidate for TASK-G4-SOURCE-002; independent review and genuine integration qualification remain UNVERIFIED. This does not expand a running pilot's rights or coverage. No paper/provider API call or host mutation was made for this candidate.

## Decision and official evidence

Choose one route, PMC OAI-PMH GetRecord with metadataPrefix=pmc and an explicit unversioned PMCID. Its current documentation distinguishes all-record metadata from reusable full-text XML, specifies the endpoint and identifier syntax, limits requests to3/s without concurrency, and requires gzip/deflate. Existing production SourceRequestHandler serializes requests across processes through PostgreSQL, retains400ms pacing and provider cooldown/daytime/lifetime budgets, and buffers bounded responses before releasing its lock. The existing HTTP handler supplies compression. No new HTTP client bypasses this production handler. [PMC OAI-PMH documentation, updated2026-08-20](https://pmc.ncbi.nlm.nih.gov/tools/oai/).

PMC's current developer documentation also lists E-utilities and BioC as supported machine interfaces. PubMed/E-utilities remains metadata/search here; BioC's transformed XML/JSON is not substituted for the JATS original. No PMC article-page scraping, arbitrary publisher URL fetching, login, CAPTCHA or paywall bypass is implemented. [PMC developers](https://pmc.ncbi.nlm.nih.gov/tools/developers/).

The updated cloud service is a useful later extension, with version-specific file sets and JSON metadata. Legacy FTP/cloud files were removed during the week of2026-08-24. Cloud version numbers reflect deposit processing; content updates can change checksums without creating a new numbered version, and higher numbers do not universally identify the preferred publication. Implementing a legacy OA API/FTP assumption would therefore be inappropriate. Cloud inventory/version/rights binding is deferred. [Current PMC AWS documentation](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/).

Free access and an OA label do not alone grant reuse. Missing permissions remain unknown; the existing ArticleRights decision accepts only explicit, unambiguous article-level CC BY4.0 or CC0 1.0 URIs, and rejects restricted/conflicting prose or spoofed/ambiguous links. The automatic policy excludes other license families pending a separately versioned review. Separately licensed photographs/media can have different terms; no linked media are fetched. The preserved XML retains its original notices and links. [PMC copyright notice](https://pmc.ncbi.nlm.nih.gov/about/copyright/), [CC BY4.0 terms](https://creativecommons.org/licenses/by/4.0/), [CC0 legal code](https://creativecommons.org/publicdomain/zero/1.0/legalcode).

PMC's copyright page still mentions FTP while its updated distribution documentation records retirement. This conflict is recorded rather than treating historical FTP guidance as current service availability. The chosen OAI route is common to both. No legal ownership or universal reuse determination follows from the parser.

## Implemented contract

`LITRADOCK_ACQUISITION_POLICY=pmc-oai-cc-v1` explicitly selects the candidate in demo configuration. Absence keeps `reviewed-xml-v1`, the two-reviewed-identity policy. Unknown values fail startup. Existing100-result search,10-item batch,512MiB storage, lifetime/admission/expiry limits remain. General non-demo research adapters are preserved. No schema, dependency or password/session contract changes.

The candidate requires an exact OAI namespace/envelope, one GetRecord/record/header/metadata/article, matching request and header identifiers, a valid repository datestamp, direct article-level PMCID and every supplied PMID/DOI, one complete body and an accepted article grant. Deleted/unsupported-format/absent records remain unavailable; malformed/ambiguous/mismatched responses fail. Redirects of every kind are rejected before a second request, including another otherwise supported provider. There is no Europe PMC fallback under this policy. Retry/backoff remains bounded by the existing90s attempt deadline, two retries and maximum10s inline delay; longer cooldowns surface rate_wait/transient to durable scheduling.

The full returned XML envelope is stored byte-for-byte with SHA-256, original/final route, format, rights URI and existing multilingual metadata. File validation additionally records the policy and OAI datestamp. The datestamp is a repository update marker, **not** a publication version; publication version is explicitly unspecified. [OAI-PMH protocol](https://www.openarchives.org/OAI/openarchivesprotocol.html). Numbered PMCID requests are denied. Validation can bind an expected response hash; a mismatch is not silently replaced. The normal UI acquires an unspecified repository snapshot, not a requested historical version. Different bytes remain distinct, even at the same datestamp; exact-file deduplication and existing versions remain intact. No source XML is rewritten to fabricate a version number.

Policy checks occur before fetch, before publication, during pending-publication recovery, before reuse of existing originals and at device download. The service description reports the selected coverage. Existing record source links and precise per-item failure reasons remain available. An unavailable item does not become a successful original or prevent permitted peers from completing. Device Save remains distinct from server acquisition.

## Qualification and rollout boundary

Reproduce offline controls with `dotnet run --project tests/LitraDock.HostedVerification -c Release -- --source-policy OUTPUT` and existing `--sources`. Inputs are explicitly synthetic, generated in the test assembly; production has no fixture fallback. `--source-policy-postgres OUTPUT` requires an explicitly authorized disposable PostgreSQL connection/database and tests the actual HostedWorker, immutable publication and mixed-item outcomes. Focused CI also runs existing demo admission/security checks; it never contacts biomedical sources.

Before using this policy with real users: independently review the immutable candidate, coordinate a minimal real OAI response outside existing two identities, verify current envelope/ID/license/content and unchanged bytes on a separate candidate, then qualify actual browser/proxy/tenant/device download and paired rollback against the deployment revision. None is passed by synthetic evidence. The live package is unchanged.

Current CHG0040 prioritizes Go migration after this freeze. Port this explicit policy and its rejection cases as compatibility requirements; do not activate broader live acquisition by copying the new configuration alone. Existing legacy originals remain preserved; switching back to reviewed-xml-v1 makes newly broader originals inaccessible through demo download but does not delete them. No reverse-migration or inherited-database qualification is claimed. Do not switch traffic until the new backend's persistence, session, worker, originals, exports, recovery and actual BaoTa management are qualified.
