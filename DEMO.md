# Restricted invited-user demo

This intermediate candidate supports real PubMed searches (up to100 results), saved selections, acquisition batches (up to10 records), original Save and CSV ZIP export. Acquisition currently permits two reviewed article XML versions, conditional on a fresh valid CC BY4.0 license URI and identifier validation: PMID31719837 / PMC6836491 / DOI10.1186/s13020-019-0270-9, and PMID33782057 / PMC8005924 / DOI10.1136/bmj.n71 (PRISMA2020 statement). It does not acquire separate media or claim publisher-PDF availability. Other results remain searchable with an explicit unavailable reason and stable PubMed/PMC/DOI links. Product accounts confer no journal access. The PRISMA publisher's [article license](https://www.bmj.com/content/372/bmj.n71) and [PubMed identity](https://pubmed.ncbi.nlm.nih.gov/33782057/?format=pubmed) were reviewed before adding its conditional acquisition route.

Acquisition stores original bytes in the server library; Save creates a download on the current device. XML and CSV ZIP need suitable device applications. This is not complete production/G4 qualification. Linux Chromium viewport390x844 is responsive emulation, not evidence for actual iOS/Android or macOS Safari. Consult exact-revision CI evidence; absence of an exception is not a passed real-source or deployment test.

## Deployment prerequisites and current limitation

A reachable Linux host with administrative access, persistent PostgreSQL18, protected disk, installed ASP.NET Core10 runtime, a project HTTPS hostname/certificate and same-host TLS proxy is required. GitHub Pages/static sites do not run this backend. No live host/access or public demo URL has been supplied/verified. Do not publish fixture-host binaries or use a researcher database as the demo database. Only a new dedicated demo database and object directory qualify.

Use the public source revision whose exact CI run passed the demo and regression checks. Download that run's `demo-candidate-linux-framework-dependent.tar.gz` and verify its SHA256 against the recorded artifact receipt, then verify its extracted files against `demo-package-hashes.txt`. The package contains app dependencies and notices; the .NET runtime and PostgreSQL are installed separately under their own terms. No Node/Chromium/document-worker installation is required for this restricted deployment: conversion, citations, uploads and research routes are denied. Keep the full normal application source for future work.

## Bounds and retained behavior

The API uses a closed demo route allowlist. Upload/restore/bundle/XLSX/conversion/citation/review/project operations are denied at the authenticated server boundary even if a client unhides controls. Saved per-account/global limits are: libraries2/20, search runs50/200, scopes200/1000, jobs200/1000. Active queue limits20/40 include search and acquisition; batch retry/resume uses the same PostgreSQL transaction lock. Global provider budgets250 requests per provider persist across restarts/dates, with existing serial provider locks, pacing and NCBI daytime/off-peak policy. Transient failures remain visible; automatic continuation is disabled for the restricted demo, and explicit batch retry still consumes quota. Search failures can be retried by submitting a new bounded search. Original acquisition reserves headroom under512MiB; a hard filesystem quota also protects the host. Do not reset counters or delete jobs to evade limits.

Single-process ingress limit600 requests/minute and10 login attempts/minute per trusted client IP complement database admission; they are not distributed DDoS protection. The known local proxy must overwrite X-Forwarded-For. The framework limiter resets on process restart, while saved-work/source quotas persist. One app instance, PostgreSQL shared locks, systemd memory/CPU/process limits and a database/disk cap define this qualification. Scaling requires a new capacity/security review. Expensive workers are not registered in demo mode; existing normal-application data and durable jobs are preserved outside this dedicated deployment.

On observed401 the client increments its authentication generation and revalidates pending headers and body completions before returning data or creating download effects. The deterministic browser regression holds real response completion and sign-in navigation, then releases after observed401. Already saved/copied data and idle/offline tabs are outside this boundary.

## Stop, retention and rollback

At the declared expiry stop `literature-demo.service` and disable public proxy routing. Expiry prevents new API/source work but is not a deletion mechanism. Preserve the protected database/object pair until the operator's stated retention deadline, handle participant access/deletion requests, then remove only the verified dedicated demo database/objects/backups under the documented policy. NCBI and proxy/server logs have separate retention; disclose actual settings. Do not process patient/private clinical data.

To revoke an account, stop API/workers and use `--account-control` with `LITRADOCK_ACCOUNT_ID` and action `disable`, `enable` or `revoke-sessions`; old sessions never return after enable. Account control preserves originals/jobs. Back up the paired database/object state before upgrades. This demo adds no database migration beyond the accepted schema; rollback to its previously tested code revision is a stopped-service operation. Keep public ingress disabled if that revision lacks these demo/late-response guards. If schema later changes, restore the matching tested database/object pair rather than guessing compatibility. Verify hashes and revoke sessions through operator recovery before restart.
