# Offline release inventory

This tool inventories the two explicitly anchored code packages: frozen demo cfd36df/CI34691326605 and operator f7b7a1d/CI34694201636. It does not rebuild, extract, load or execute their binaries, launch PostgreSQL, query biomedical sources or qualify a deployment. `inventory.py` reuses the existing bounded archive verifier and adds per-file provenance. The application packages, source refs and credential review identity remain unchanged.

Use Python3.12+ and the repository-pinned .NET SDK10.0.400. Build the small NugetProof helper against the SDK's own NuGet assemblies; its lock contains no third-party package dependency. Populate the eight application NuGet dependencies through the existing locked restore in an authorized preparation step, or use an already populated cache. Vulnerability audit is explicitly disabled for this offline preparation, not reported as a pass. Inventory generation performs no network request. NuGet may contact registries during initial restore, and `gh run download` fetches the retained CI artifacts; distinguish those preparation operations from offline verification.

```text
dotnet restore src/LitraDock.Hosted --locked-mode -p:NuGetAudit=false
dotnet restore deployment/inventory/NugetProof --locked-mode -p:NuGetAudit=false
dotnet build deployment/inventory/NugetProof -c Release --no-restore
python deployment/inventory/inventory.py demo --artifact-dir <retained-demo-artifacts> --source-repository <exact-public-Git-clone> --nuget-cache <NuGet-cache> --helper build/NugetProof/Release/net10.0/NugetProof.dll --output <new-demo-inventory.json>
python deployment/inventory/inventory.py operator --artifact-dir <retained-operator-artifacts> --source-repository <exact-public-Git-clone> --nuget-cache <NuGet-cache> --helper build/NugetProof/Release/net10.0/NugetProof.dll --output <new-operator-inventory.json>
```

Input directories must contain each original archive and its original emitted hash manifest. Names, source commits, run IDs, manifest hashes and archive hashes are closed constants in `RELEASES`. The Git clone must retain both full commits. Working-tree edits are ignored: source metadata comes from `git show <exact-commit>:<path>`. A caller-supplied latest branch or recomputed digest is not a substitute for these anchors. Output is a new exclusive file; no overwrite or merge is supported. Exit2/BLOCKED denotes failed input, integrity, provenance correspondence, tooling or output conditions. Missing dependency archives do not become a successful partial byte-proof.

Every shipped member is classified. Third-party runtime/native files must exactly match the `.deps.json` member of a NuGet archive, whose unsigned-content hash must match the exact source lock. NuGet's own `GetContentHash` and `ValidateIntegrityAsync` handle signed packages; a signed archive's raw hash can differ from the lock content hash. Both package SHA256 and locked content hash are retained. This verifies content integrity against the reviewed lock; it does not validate publisher identity, certificate chains, revocation or vulnerability status. See the [NuGet primary implementation](https://github.com/NuGet/NuGet.Client/blob/dev/src/NuGet.Core/NuGet.Packaging/PackageArchiveReader.cs) and the actual SDK helper version in each inventory.

HTML/CSS/JavaScript and shipped documents match exact source bytes. Gzip/Brotli variants are decoded with bounds and compared to those source bytes. First-party assemblies/PDBs and SDK-generated metadata are associated with the exact successful CI build and their archive hashes; this is not an independent reproducible compilation attestation. The native apphost's exact host pack is unresolved. SQLitePCLRaw's package version does not establish its bundled SQLite engine/build version. Declared nuspec licenses do not establish complete notices for bundled subcomponents or legal ownership; all eight inspected packages lack packaged LICENSE/NOTICE members. Keep these gaps visible.

The deterministic JSON contains no timestamp or local absolute path. It records source blob SHA256s, package/member identities, license declarations, RID distinctions and unresolved provenance. `.NET`/ASP.NET framework requirements, PostgreSQL/proxy/OS tools and the optional general-research Node/Chromium/font/document-worker dependencies are external. The document worker is absent from these app archives and disabled by the restricted demo. Its lock and pinned asset metadata are recorded separately, including the known citeproc license-metadata conflict. Multiple bundled native RIDs are not evidence of supported platforms.

Run `tests/deployment/test_inventory.py` with `INVENTORY_INPUTS` containing `demo/` and `operator/` artifacts, `INVENTORY_SOURCE`, `INVENTORY_NUGET_CACHE`, `INVENTORY_HELPER` and a new `INVENTORY_OUTPUT` directory. Optional arguments specify a result JSON path. Without actual inputs, three real-package groups explicitly skip. Controls cover independent missing/extra/changed members even when the mutated outer archive hash is supplied, duplicates/traversal/links, wrong manifest/lock/source, corrupted signed NuGet and Brotli inputs, exact two-release generation, deterministic regeneration and overwrite refusal. Focused `inventory-ci.yml` runs these plus the separately corrected preflight PG tests; it does not rerun product, browser or biomedical suites.

## Update and rollback boundary

Keep the original archive, manifest, inventory, exact source/CI references and protected database/object-pair backup together under operator-controlled retention. These GitHub artifacts currently expire after seven days; checked-in hashes are not durable binary storage or signatures. Do not invent a signing identity or infer archive authenticity solely from a checksum supplied alongside the archive.

The frozen demo and operator packages use schema4 and identical migrations. Credential rotation adds an operator command without a schema migration, and preserves account enablement and data identity. The operator archive carries CREDENTIALS.md instead of DEMO.md; the existing demo-specific package preflight intentionally does not accept it as the frozen launch package. Selecting it as a deployable successor requires separate review and host qualification.

Do not overlay package files in place or mix versions based on shared assembly version `0.2.0-local`. Select the complete hash-verified package while service/workers are stopped. Preserve protected configuration, data roots, database and prior package independently. A code rollback to schema-compatible code must not restore an old account/session database to resurrect revoked credentials; use the established paired recovery procedure for a deliberate data restore. Compatibility here is established from source migrations and operator logic, not a performed target update or rollback drill.

Before release, complete native/apphost and license-notice provenance, current vulnerability review against the exact runtime/dependencies, clean-user installation and upgrade tests, signing/authentic distribution, durable artifact/backup retention, and actual HTTPS/private-path/proxy/account/recovery/capacity/device checks. None is passed by an inventory. No host access or purchase is required to reproduce this bounded evidence.
