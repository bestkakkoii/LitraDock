# ADR 0015: Exact PMC deposit PDFs through the existing acquisition worker

Status: implementation candidate; activation requires scoped review and application qualification.

The source is the anonymous HTTPS PMC Article Datasets service on `pmc-oa-opendata.s3.amazonaws.com`. One bounded prefix listing must identify exactly one deposit; larger version numbers are not interpreted as preferred editions. JSON must bind the saved PMID, PMCID and DOI, published/non-retracted/non-OCR status and CC BY category. The advertised version-specific JATS checksum and the already reviewed complete CC BY 4.0 article grant then qualify the advertised PDF checksum. Unknown, multiple, restricted or missing cases remain held with direct landing links. Metadata availability alone grants no permission. [Official version and access rules](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/).

The adapter accepts the observed cloud JATS 1.4 declaration without fetching its DTD, and its unnamespaced grant structure separately from the OAI namespace. Object responses currently use `binary/octet-stream`; admission still requires the advertised MD5 and format parser. MD5 is only the source's transfer-consistency evidence; immutable file identity uses SHA256. Retain the bounded raw version list, JSON and JATS with each original. The existing 256 MiB store budget includes these evidence bytes. Saved files are archival snapshots, not a claim of current NLM content. [Dataset fields and redistribution terms](https://pmc-oa-opendata.s3.amazonaws.com/README.txt).

Use pdfcpu `v0.15.0`, Apache-2.0, for read-only PDF parsing and validation, with no configuration directory, network/link validation, credentials, optimization or rewriting. Compatibility mode is deliberate: strict mode rejected a genuine PDF's omitted XObject subtype and another's FontFamily metadata newer than its declared PDF version. Both retained PDFs pass compatibility mode and the independent pypdf reader. This is not PDF/A, malware, accessibility, physical-device or complete rendering-fidelity certification. Cap input/encoded streams at 8 MiB, decoded/image allocations at 16 MiB, object/xref counts at 100,000, object streams at 10,000, recursion at 64 and pages at 1,000; serialize parser calls. Resource limits and malformed-input controls are required, not assumed from file extension. [Pinned parser](https://github.com/pdfcpu/pdfcpu/blob/v0.15.0/pkg/api/validate.go), [pinned resource configuration](https://github.com/pdfcpu/pdfcpu/blob/v0.15.0/pkg/pdfcpu/model/configuration.go).

Schema 3 adds immutable requested format to batches/plans and actual format plus bounded proof bytes to originals. Omitted format remains XML; changed-format request replay conflicts. Every reuse explicitly selects the format. The single existing worker, shared source accounting, retry ceiling, capacity-parent-child-item locking and lease publication fence remain authoritative. Four requests at most form one successful cold attempt; explicit retries count again and may stop earlier. Cloud requests use at least one-second pacing and existing Retry-After/lifetime/day limits. No new source registration, publisher scraping or authentication is introduced.

Stopped-service `migrate-pdf` upgrades schema 2 transactionally under the admission lock. `rollback-empty-pdf` refuses if any PDF request, plan, original or proof exists, including cancelled requests. After use, retain schema 3 and a qualified compatible binary with PDF disabled if needed; restoring an old snapshot over new research is not rollback. Prior XML bytes, IDs, libraries, accounts and plan membership remain intact. Paired backup/isolated restore and actual old-binary refusal are deployment gates.

The UI explicitly distinguishes requested PDF acquisition, server progress and subsequent device Save. Existing child ZIP includes original bytes plus all held reasons and source links. Default selection covers only enumerated saved records (maximum 100), never the provider total; acquisition requires an explicit click. CHG0044 JSON/JSONL export follows separately. CHG0046 permits a later clearly labelled full-text renderer only after verified absence of a source PDF and complete licensed text; denial, challenge or timeout is not absence, and no renderer is part of this decision.
