# ADR-0027 — Durable saved-run selection

Status: PROPOSED_DEFAULT implementation; independent review and deployed qualification pending.

A researcher's explicit choices must survive reopening a saved PubMed run. Schema 9 adds a default policy per library/run, exceptions per saved Search ID, and UUID-bound action receipts. Untouched runs default to all saved records without a read side effect. All/none actions reset the policy and exceptions; page actions add/remove only page members. New saved members follow the policy, so continuation preserves explicit deselections. Provider matches are not selected until saved. Existing saved-run identity, query/filter/relevance meaning, capture limit of 1,000, and PDF limits of 10 per batch / 100 per plan stay unchanged.

The public revision is the stored action counter plus append-only saved membership count. A new saved page therefore invalidates stale mutation/export intent. This relies on saved membership being append-only within an individual run; any future removal/replacement or arbitrary membership editing must introduce a separate monotonic membership version. Rank and Search ID establish deterministic order. Run/record foreign keys and the existing authenticated library boundary prevent cross-scope exceptions. Mutation admission shares the existing capacity lock, serializes on the saved run, compares revision, and commits choices plus receipt atomically. An exact request replay returns its original receipt, even after write admission is disabled. A changed UUID intent or revision conflict cannot overwrite later choices.

Counts and all selected IDs share one database snapshot. Metadata details are included only for at most 100 selected records and at most 4 MiB of stripped metadata; the response explains a missing detail set. The entire ID selection remains available up to 1,000. An action contains at most 100 distinct IDs; the database admits at most 20,000 stored selection action receipts and preserves earlier data when that bound is reached. Raw XML/full-text metadata is excluded from selection responses. Admission is rechecked through response handoff. Browser cancellation or a lost response cannot imply that a transaction rolled back: uncertain intent retains its UUID/payload for deliberate retry, or the user reloads the server's current choice. Prior browser-only choices from before this migration cannot be reconstructed.

Selected CSV/XLSX/JSON/JSONL exports use the exact displayed selection revision and one snapshot of membership, metadata and saved source outcomes. They reject empty, stale, inconsistent or oversized data without a partial file. Headers and document/column scope identify selected saved records, revision, and saved count. Whole-run exports continue to cover all saved records independently of checkboxes. PMID, PMCID, DOI, durable Search ID and individual Search Run ID remain distinct; unresolved source outcomes stay unresolved. Creating a PDF request copies its admitted membership into that existing immutable request, and later checkbox changes cannot mutate it.

Migration is transactional from schema 8, creating three empty tables and one version row. Existing research/original tables are unchanged. Downgrade to schema 8 is permitted only while all three new tables are empty. Once any choices/receipts exist, a compatible schema-9 reader with `SelectionWriteEnabled=false` is the supported containment path; the old schema-8 binary cannot read schema 9. Preserve the data and backups for a reviewed forward repair. Do not delete choices or restore an old dump over new research to enable a binary downgrade.

Release qualification must include a fresh private backup, isolated restore, preserved research hashes, empty-schema migration/rollback, independent frozen review, guarded runtime/config switch, exact artifact identity, and actual saved-record UI reload/export checks. Synthetic fixture counts do not prove live provider capacity. Extending query capture beyond 1,000 is a separate dependency, and no PDF execution expansion follows from this decision.
