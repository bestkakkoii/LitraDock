# ADR-0016: Versioned structured research export


POST the existing `/api/libraries/{library}/exports` with exactly one `runID` or `batchID`, and `format:"json"` or `format:"jsonl"`. Authentication, CSRF and scope fences are unchanged. These formats export **every saved record in that run or batch**, independent of checkbox selection or current page. Label controls **Export saved run JSON / JSONL** and **Export batch JSON / JSONL**; explain this scope next to the controls. Do not imply selected-only or all-provider-match export. Existing CSV/XLSX/PDF/ZIP actions remain.

Success: UTF-8 `application/json; charset=utf-8` or `application/x-ndjson; charset=utf-8`, attachment `litradock-research.json` or `.jsonl`. JSON is a versioned document. JSONL has one manifest object on line1, then one `{type:"record",record:...}` object per line, ending with newline. The manifest has the same fields as the document except records; its type is `manifest` instead of `document`. Escaped newlines inside strings never create extra records. The browser verifies media type and existing session/body/download generation before Save; an error body must never become an export file.

Document fields: `schema:"litradock.research-export"`, `schemaVersion:1`, `type:"document"`, `generatedAt` UTC string, `scope:{kind:"run"|"batch",runId:string|null,batchId:string|null,selection:"all_saved_scope"}`, `counts:{exportedRecords,scopeRecords,providerMatches:number|null,retrievedRecords:number|null}`, `queryContexts:[...]`, `records:[...]`. Batch aggregate provider/retrieved totals are null because related searches overlap and cannot honestly be added. Each query context carries `runId`, exact `query`, `state`, nullable `reason`, `providerMatches`, `retrievedRecords`, `requestedLimit`, `retrievalComplete` (settled complete state and retrieved==provider count), and nullable actual `submittedAt` from the associated stored search job. Raw snapshots and worker metadata are not exported.

Each record has string `searchId`, `runIds:[]`, `identifiers:{pmid,pmcid,doi}`, `publication:{title,authors,year,journal,publicationDate,articleNumber,pages,abstract,publicationTypes,retrievedAt}`, `sourceLinks:{pubmed,pmc,doi,doiLinkState}`, `acquisition:{state,reason,requestedFormat}` and `originals:[]`. Missing scalar values are explicitly null; identifier values remain strings. Run scope has null acquisition fields because it does not select a particular batch attempt. Batch scope preserves that attempt's historical state/reason, including held/retry/cancelled states.

Original descriptors carry `kind:"source_original"`, `format`, `mediaType`, nullable `depositVersion`, nullable `version`, `sha256`, `bytes`, `sourceUri`, `rightsUri`, `repositoryStamp`, `acquiredAt`, `availability:"not_revalidated"`. This metadata-only export reports stored original identity, not permission to download now: current Save separately revalidates bytes and rights. No raw original, proof XML/JSON, full text or derived PDF is embedded. Supported PDF deposit version is derived only from its exact stored official version path; unsupported provenance stays null. No new acquisition or PDF parsing is triggered by export.

Server limits: at most1000 records,1000 query contexts and1000 original descriptors; stored metadata and query-text budgets checked before reading, output at most8MiB, bounded field lengths, consistent read-only transaction. Missing scope, mixed scopes, inconsistent counts/membership, malformed stored selected metadata and excessive output fail before any partial file is written. No silent truncation. Arbitrary metadata keys, account/login/session/token/CSRF/password, admin configuration, worker leases, raw snapshots and proof bodies are excluded by typed allowlist.


Decision: use Go standard-library typed JSON serialization with a shared record model for JSON and JSONL. This adds no runtime dependency or schema migration. CSV/XLSX remain separate established formats; their record shapes are not used as a lossy intermediary. UTF-8 JSON strings preserve formula-like values as inert data. No external LLM service receives exports automatically.

A repeatable-read, read-only PostgreSQL transaction fixes membership, publication metadata, query counts and original descriptors to one snapshot. Encoding completes before HTTP headers or body are written. Operational database errors are not included in the public error response. Limits are 4 MiB stored metadata, 1 MiB query text, 256 KiB per selected publication field, 10,000 query associations and 8 MiB final output. The UI cap and provider retrieval budgets do not change.

Compatibility: schema version 1 is explicit. Readers should validate the version and declared scope before interpreting records. A future breaking field or semantic change requires a new version. This additive server release retains database schema 3 and existing originals; rollback to the preceding schema-3 binary preserves saved data but removes JSON/JSONL routes. Independent Python parsing establishes interchange fidelity, not physical-device, spreadsheet, legal or vulnerability qualification.
