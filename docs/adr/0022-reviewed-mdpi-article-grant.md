# ADR0022 — one additional complete article grant profile

Status: candidate, pending independent source-policy review and genuine application qualification. This changes a rights representation profile; it does not expand supported license families, routes, versions, acquisition limits or source budgets.

The cloud adapter already requires one complete unambiguous deposit version, agreement with saved PMID/PMCID/DOI, explicit published/open/non-retracted/non-OCR metadata, and advertised checksums binding the JATS and PDF. The article validator then recognized only one complete grant template. A captured MDPI deposit carries a different explicit whole-article CC BY4 template and was held at the structure check. A metadata `CC BY` code alone remains insufficient.

The additional profile applies only to non-namespaced cloud JATS1.4 after the existing article identity checks. Permissions must contain exactly one copyright statement, matching four-digit copyright year, and one lowercase `open-access` license. The license must contain exactly one ALI CC BY4 reference with the observed text-mining attributes, followed by one complete English paragraph with the explicit article grant and one exact CC BY4 link. The complete paragraph, structure, attribute namespaces and intervening text are checked. Only year substitution and whitespace are normalized. An arbitrary license URL or prose substring cannot admit a file.

This deliberately narrow grammar does not infer permission from publisher identity. Extra grants, component permissions/credits, conflicting notices anywhere outside the grant (including abstract and front matter), unknown scope attributes, inherited base/scope, future dates, unfamiliar namespaces, changed wording and inconsistent repository rights metadata remain held. The notice guard is conservative and may hold legitimate scientific text mentioning reuse; it is not a general legal-language interpreter. Third-party exceptions need separately reviewed evidence before any broader profile. Known repository license, copyright suppression, legal suppression and embargo fields must be consistent when present; duplicate fields or intervening hidden text are rejected. Original bytes are never modified.

JATS documents both license prose and optional ALI references, rather than requiring one publisher's presentation. Its documented flexibility motivates checking an additional observed complete profile, not accepting every legal JATS structure. [JATS1.4 license](https://jats.nlm.nih.gov/archiving/tag-library/1.4/element/license.html), [permissions](https://jats.nlm.nih.gov/archiving/tag-library/1.4/element/permissions.html).

PMC's supported cloud service provides versioned objects and checksum metadata. Its version numbers reflect processing order and do not necessarily indicate a preferred version; changed bytes may retain the same version. Existing uniqueness and checksum checks therefore remain. [PMC AWS documentation](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/).

The synthetic fixture contains only the observed rights boilerplate with a substituted year, not a paper or operational grant. Its underlying attribution statement and CC BY4 reference are retained; the genuine source is *Genetics and Epigenetics in Asthma*, DOI10.3390/ijms22052412, PMCID PMC7957649, deposit1, ©2021 by the authors, licensee MDPI. [Article identifier](https://doi.org/10.3390/ijms22052412), [CC BY4 terms](https://creativecommons.org/licenses/by/4.0/). Full captured article evidence stays outside the distributable repository.

Schema6, original storage, proof schema, worker/session/admission controls and export formats are unchanged. Previously accepted proofs remain readable. An older binary conservatively holds new-profile originals when it revalidates them; a binary rollback must describe that temporary availability loss and must not delete acquired research or rewrite proof bytes. Public activation requires an independently reviewed immutable code delta, qualified package/source mapping and a separately metered genuine PDF acquisition/export flow. Offline replay does not establish a live PDF download.
